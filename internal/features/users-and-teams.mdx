## Overview

Users & Teams covers user management, invited users, manager relationships, role assignment, and team-level visibility. It is the foundation for access control, coaching views, assignments, and reporting.

## How to Invite New Users

Customer guide: [Invite Users](/guides/invite-users).

1. As an organization administrator, open **Settings → Tenant Settings → Team → Users**, or go directly to [User Management](https://app.getzell.com/settings/team/users).
2. Click **Invite User**.
3. Select the **Workspace**. The active workspace is used by default; a single workspace is selected automatically and its picker is hidden. Without a workspace, the remaining fields and submit button are disabled.
4. Enter one **Email** address and choose **User** or **Admin**. These are the two roles exposed by this form; User is the default.
5. Optionally select a **Group**, a **Manager**, and, for User invitations, a **Course**. The group list follows the selected workspace, and changing workspace resets the group selection.
6. Click **Invite**. The recipient receives an email with a link to complete setup. New users enter their name and password using the invited email address.

German UI: **Einstellungen → Mandanteneinstellungen → Team → Benutzer → Benutzer einladen**, then **Einladen**.

## Aircall Setup After an Invitation

For Aircall-connected tenants, a successful invitation can open **Finish Aircall setup** after the invitation dialog closes. It shows the invited email address and reminds the administrator to connect the person's Aircall number to Zell. The reminder applies to successful invitations for either role exposed by this form; it does not wait for the recipient to accept the invitation.

Click **Connect in Aircall** to open the tenant's Zell integration in a new tab. In Aircall, choose **Connected numbers → Add numbers** and select the person's Aircall numbers. This remains a manual Aircall action. Sending an invitation, opening the link, or dismissing the popup does not connect numbers or verify that setup is complete.

| Condition | Reminder behavior |
| --- | --- |
| Invitation succeeds | The form resets, the invitation dialog closes, and the normalized email is added to local reminder state. Failed or duplicate invitations do not add an email. |
| Aircall status is connected | The reminder requires `GET /integrations/aircall` to return `connected: true`. A missing tenant ID disables this status query. Disconnected or unavailable status does not show the reminder. |
| Integration details are loading | After a successful invitation for a connected tenant, the user-connections query loads the integration details. The popup can appear during loading; without a link, its button shows **Preparing Aircall link…** and is disabled. |
| Integration is inactive | If the returned integration has `active: false`, the reminder is hidden. The popup does not check whether the particular invitee already has connected numbers. |
| Administrator dismisses the popup | Dismissal clears the remembered emails. This does not revoke the invitation or save a completion flag. A later successful invitation can show a fresh reminder. |
| Tenant changes or page reloads | Reminder emails are local component state, not persisted. Emails recorded for one tenant are hidden in another tenant. A page reload removes that state. |

The integration query keys include the tenant ID. The reminder requests `GET /integrations/aircall/user-connections` only while it has invited emails and connected status. The link uses the returned integration name and ID: `https://dashboard.aircall.io/integrations/hub/{integrationName}/{integrationId}/general`, where the name is lowercased, whitespace is replaced with underscores, and the result is URL-encoded. The invitation form still accepts one email at a time; the reminder deduplicates any emails held in its local state.

**Aircall support checks**

- **Popup did not appear:** confirm the invitation succeeded, the invitation dialog is closed, and the current tenant's Aircall status is connected. A status-request failure shows a connection-status error toast and leaves the reminder hidden. Also check whether the integration-details response reports `active: false` or the reminder was dismissed.
- **Aircall link failed to load:** the invitation remains sent. When no link is available, **Retry Aircall link** refetches integration details; it does not resend the invitation. Investigate the user-connections endpoint if retries fail.
- **Numbers still need setup:** opening the dashboard does not complete or verify the Aircall connection. Check **Connected numbers** in the Zell integration in Aircall and add the intended numbers there.

## Permissions and Seat Limits

All invitation endpoints require authentication and an admin role (`ADMIN` or `INTERNAL_TOOL_ADMIN`). `TEAM_LEAD` alone cannot list, create, revoke, or resend invitations, even though the settings navigation includes team pages for team leads.

The invitation form exposes **User** and **Admin** only. Other platform roles listed above are not invitation options in this UI. Candidate invitations belong to the separate [Hiring workflow](/guides/hiring-module).

Seat usage is the number of regular, non-test `USER` accounts plus unaccepted `USER` invitations in the tenant. The page disables **Invite User** when a configured limit is reached, and the create endpoint also enforces the limit before creating an invitation. This check applies before selecting or processing the invited role.

## Invitation Lifecycle

| Stage | Behavior |
| --- | --- |
| Create | The UI trims and lowercases the email. The backend stores the tenant, role, random token, seven-day expiry, and workspace/group/course/manager configuration. |
| Duplicate | The create endpoint returns a conflict if an invitation record already exists for the same email and tenant. The UI also checks the currently loaded invitation list. |
| Email | The invitation creation callback queues the tenant-invitation email with a `/login?token=...` link. Demo tenants intentionally do not receive invitation emails. |
| Pending | The list returns records with `acceptedAt = null`, newest first, filtered by workspace when one is active. Expired invitations can still appear until removed; the pending query does not filter by expiry. |
| Accept | Token resolution and invitation registration reject expired or already accepted links. Registration uses the invitation's email, assigns access, marks the invitation accepted, applies its workspace/manager/groups, and enrolls the user in the selected course. |
| Revoke | Deleting an unaccepted invitation removes its record and invalidates the link. Accepted invitations cannot be revoked through this endpoint. |
| Resend | The backend resend endpoint rotates the token and sets a new seven-day expiry. The token-change callback queues a new email. Accepted invitations cannot be resent. |

## Pending Invitations and Replacement Emails

The Users page displays **Pending Invitations** below the user table, with email, role, date, and a trash button. Accepted invitations disappear from this list. Check the active workspace when an expected invitation is missing.

The current user-management UI provides cancellation but no dedicated resend button. To send a replacement through this UI, delete the old pending invitation and invite the address again with the intended assignments. The old link stops working, and the recipient must use the newest email.

The form accepts one email at a time. There is no bulk invitation control for regular users on this page.

## Support Checks

- **Access denied:** verify the caller has an admin role; team-lead navigation visibility does not grant invitation API access.
- **Invite disabled:** check the seat counter and pending User invitations. Within the dialog, also check workspace selection.
- **Already invited:** check other workspaces and whether the invitation was accepted. The duplicate check spans the tenant, while the displayed pending list can be workspace-filtered.
- **No email:** check the address and spam folder, confirm the tenant is not a demo, and inspect notification delivery if needed. Creating the record and delivering its email are separate operations.
- **Expired link:** create a replacement through the UI, or use the admin resend endpoint. Do not describe expired pending records as valid links.

## Invitation APIs

| Method and path | Purpose |
| --- | --- |
| `GET /admin/invitations` | List unaccepted invitations; optional workspace filter. |
| `POST /admin/invitations` | Create an invitation after admin, seat-limit, and duplicate checks. |
| `DELETE /admin/invitations/:invitationId` | Revoke an unaccepted invitation in the tenant. |
| `POST /admin/invitations/:invitationId/resend` | Rotate the token, renew expiry, and trigger a replacement email. |
