## Overview

Zell AI is the assistant experience inside the platform. It helps users ask questions, inspect application data, and work through AI-assisted workflows.

## Scorecard Creation

Scorecard creation is a review-and-confirm workflow, not a one-step write:

<Steps>
  <Step title="Gather and summarize scope">
    Zell AI establishes the workspace, language, call type, scorecard purpose, and approved criteria, then shows the proposed scorecard structure to the user.
  </Step>

  <Step title="Confirm before generation">
    The user must confirm the proposal in a prior turn. Only that confirmation authorizes Zell AI to call `create_scorecard`; asking for analysis or optimization does not.
  </Step>

  <Step title="Generate a reviewable draft">
    Zell AI generates `scorecardData` and passes it to the scorecard form. The generated structured output must include at least one scoring signal. Customer-supplied categories are passed as one complete verbatim criteria block and become one signal per category in the same order.
  </Step>

  <Step title="Review and explicitly save">
    The user reviews the complete generated draft, including signal count, order, names, language, descriptions, guidelines, rubrics, methods, weights, call type, and workspace. Saving is a separate explicit action; generating the draft does not persist or activate it.
  </Step>
</Steps>

<Warning>
Confirmation to generate a draft is not confirmation to save it. Never describe a generated scorecard as created, updated, saved, or live until the separate save action succeeds.
</Warning>

The backend validates generated scorecard output with a stricter schema than persisted scorecard metadata, so a model response with an empty signal list is rejected instead of creating a scorecard that cannot score calls. The Anthropic structured-output schema conversion must unwrap defaulted arrays so `signals` is exposed to the model as an array with `minItems`, not as a generic string field.

For the real-call field flow and the distinction between Evaluation Criteria and User Guidelines, see [Scorecards & Signals](/internal/features/scorecards-and-signals).

## Course Creation Language

The `create_course` tool generates a course draft for review and a separate save action. Its `language` argument controls the generated course, including titles, descriptions, module content, and the language used to select or create practice agents.

The tool input schema instructs the assistant to choose the language in this order:

1. The user's explicit language request
2. The uploaded document's language
3. The conversation's language
4. English (`en`) as the default

This precedence is guidance for the assistant when supplying the required `language` string. The schema does not detect a language or insert a default itself. Once supplied, that language takes precedence over the source document, course title, and target market. For example, a course about selling in France can use English throughout.

### Backend Flow

| Stage | Language handling |
| --- | --- |
| Tool execution | Copies `CreateCourseInput.language` into `CourseCreationContext.language`. |
| Structure generation | Passes the context language to `buildStructurePrompt` and refines `CourseOutputSchema.language` to require an exact match. |
| Module content | Passes the context language to the prompt for HTML content and practice instructions. |
| Practice agents | Uses the context language to match agents by call type and language, and to create a missing agent. |
| Tool result | Returns the draft as `courseData` and includes `Course language: <code>` in the success message, followed by the review-and-save instruction. |

If the model returns a different language code, structure validation fails. The pipeline retries structure generation twice, then reports failure with no course draft if the mismatch persists. Module content generation and agent resolution start only after structure generation succeeds.

The validator checks the returned language code; it does not detect the language of every title or paragraph. Also, existing agent-resolution fallback behavior can select the first available agent when no matching agent is available, including after automatic agent creation fails. That fallback can have a different language. Inspect the assigned agent when investigating a practice-call language mismatch.

Generating the draft does not save the course. Agent resolution can create supporting personas and practice agents during draft generation; course persistence remains a separate action.

### Troubleshooting Unexpected French Content

Find the relevant Langfuse trace and compare the `create_course.language` argument, structure prompt, structure response's `language`, and module content prompts. Check the generated prose as well as the language code. A French target market or French source document should not override an explicit English request once `language: "en"` reaches the pipeline.

If the tool argument is already wrong, inspect the user's request and the assistant's language selection. If the tool argument is correct but downstream prompts use another language, investigate backend language propagation. If prompts and codes are correct but prose is French, investigate generation compliance. For practice calls, check the assigned agent's language and agent-creation or fallback logs. Do not attribute French course text to display-language settings without trace evidence.

## Model Picker Defaults

When the Zell AI chat model list loads, the frontend preselects an Opus model when one is available. This is a frontend picker default only; it does not change the backend model list or the backend-declared default.

The fallback order is:

1. First model from `GET /admin/zell-ai/models` whose id includes `opus`
2. Backend-declared default model from the same response
3. First model returned by `GET /admin/zell-ai/models`

Once a user explicitly picks a model in the Zell AI chat, the frontend does not clobber that choice when model data reloads. Support should treat unexpected initial picker values as a model-list ordering/default issue first, and unexpected changes after selection as a frontend state issue.

Source: `src/hooks/zell-ai/modelSelection.ts`, `src/hooks/zell-ai/useZellAiChat.ts`
