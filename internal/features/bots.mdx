## Overview

Bots are AI agents used for training conversations. They define the simulated counterpart, scenario behavior, voice configuration, language, and scoring/evaluation setup used in practice calls.

## Mood Controls

The admin **Create simulation** settings and the agent editor's **Call Settings**
tab show explanations beneath the mood options. The selected mood's explanation
also appears below the field; the closed selector shows only the mood name.
These descriptions are presentation-only. They do not change the stored mood
values or the existing call-type restrictions.

| Mood | Explanation |
| --- | --- |
| Nice (`NICE`) | Friendly but busy. May hang up if you take too long to get to the point. |
| Less Rude (`LESS_RUDE`) | Skeptical. Wants to discuss their problems before hearing your pitch. |
| Rude (`RUDE`) | Impatient and dismissive. Will only listen if you quickly show how you can help with their problems. |
| Sassy (`SASSY`) | Witty and unpredictable. Pushes back and takes the conversation off topic. |

### Available moods

Both controls use `getAvailableMoods(callType, allowRandom)` to determine their
options. The second argument defaults to `false`.

| Call type | Available moods |
| --- | --- |
| `COLD_CALL` | Nice, Less Rude, Rude, Sassy; also Random when `allowRandom` is `true` |
| `DEMO`, `PROPOSAL` | Less Rude |
| `DISCOVERY` | Less Rude, Sassy |
| `WARM_CALL` | Nice, Less Rude, Rude |
| `CHECK_IN` | Nice |
| `CUSTOMER_CARE` | Rude |
| `GATEKEEPER`, custom/unrecognized call types, or an empty call type | Nice, Less Rude, Rude, Sassy |

Random (`RANDOM`) has no explanation. It is offered only for `COLD_CALL` when
the caller enables `allowRandomMood`. The current `CreateSimulationForm` and
`EditAgentForm` both enable that prop. No selected-mood explanation is displayed
for Random or a value absent from the current option list.

### Creation and editing behavior

- **Create simulation:** `SimulationSettings` disables the mood selector until
  a call type is selected. Its `useSimulationSettings` hook preserves the
  current mood when the new call type supports it, or resets it to an empty
  string otherwise. Other form values are retained during this call-type
  change. The hook also clears `RANDOM` when `allowRandomMood` is disabled.
- **Agent editing:** `CallSettingsTab` derives its options from the watched
  call type and binds the selected mood to the form's `mood` field. Its
  call-type control updates the `type` field; this tab does not perform the
  creation hook's mood-reset operation when the call type changes.

The shared option renderer keeps descriptions outside the selected label.
Described options expose their supporting text through `aria-describedby`.
The creation field also links to its selected explanation, while editing uses
`FormDescription` with a polite live region. Selection and submitted values
continue to use the existing mood codes.
