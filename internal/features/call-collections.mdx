## Overview

Call Collections let users save calls for later review, coaching, enablement, or team sharing. Collections are used from call and snippet surfaces where a user wants to keep a call as an example.

## Call Analysis Breadcrumbs

When a user opens Call Analysis from a collection, the route keeps collection breadcrumb context. The breadcrumb trail links back to Call Collections and the originating collection title when available.

Source reference: `src/components/analysis/useCallAnalysisNavigation.ts`.

## Visibility and Permissions

A collection is either **Private** (only its author sees it) or shared with the **Tenant** (everyone in the tenant sees it). Sharing a collection also lets teammates add to it.

| Action | Author | Admin | Other tenant member |
|---|---|---|---|
| See the collection | ✅ | ✅ | Tenant collections only |
| Add calls or snippets | ✅ | ✅ | Tenant collections only |
| Remove calls or snippets | ✅ | ✅ | ❌ |
| Rename, change visibility, delete | ✅ | ✅ | ❌ |

"Admin" means the `ADMIN` or `INTERNAL_TOOL_ADMIN` role. A `USER` can still only add their own calls, so a rep cannot put a teammate's call into a shared collection.

The Add to Collection dialog lists every collection the user can add to: their own, every tenant collection, and all collections for admins. On collections the user does not own, an already-added call shows as added but cannot be removed from the dialog.

<Note>
  If a rep sees "No collections yet" in the dialog, nobody in their tenant has shared a collection and they have not created one.
</Note>
