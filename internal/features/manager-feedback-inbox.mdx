## Overview

The Manager Feedback Inbox is the follow-up queue for managers and admins. It shows reps who have replied to coaching feedback where no manager or admin has responded after the latest rep reply.

This inbox is separate from the rep-facing [Feedback Inbox](/internal/features/feedback-inbox).

<Warning>
**The Manager Feedback Inbox UI was removed from the frontend.** Admins and team leads now see the [Manager Home](/internal/features/manager-home) at `/` instead of the "What you have to do" pending-replies queue. The frontend components (`ManagerInbox` and the `ManagerSnippet*` viewer in `src/components/dashboard/manager/`) and hooks (`useGetManagerPendingReplies`, `useGetNextManagerPendingReply`, `useSkipManagerPendingReply`) no longer exist.

The backend endpoints are still present in `zell-backend-ts` (`src/api/admin/feedback/feedbackRouter.ts`), so the pending-reply logic below still describes the API. The UI flow sections describe the removed frontend and are kept for reference.
</Warning>

## Key Concepts

<CardGroup cols={2}>
  <Card title="Pending Reply" icon="reply">
    A feedback thread becomes pending when a regular user replies and no manager/admin has replied afterward.
  </Card>

  <Card title="Rep Queue" icon="users">
    The inbox groups pending snippets by rep, then by call, so managers can work through one teammate at a time.
  </Card>

  <Card title="Snippet Viewer" icon="panel-right">
    Managers see transcript context, score, coachability, feedback, replies, and audio when available.
  </Card>

  <Card title="Skip" icon="circle-slash">
    Skipping creates an internal manager skip reply instead of deleting the feedback.
  </Card>
</CardGroup>

## How It Worked (Removed UI)

<Steps>
  <Step title="Open the Home Page">
    Users with manager roles saw the Manager Feedback Inbox instead of the rep-facing inbox. They now see the Manager Home.
  </Step>

  <Step title="Load Pending Replies">
    The frontend requested `/admin/feedback/pending-replies`.
  </Step>

  <Step title="Choose a Rep">
    The left column listed reps with pending snippets. Each row showed the remaining count and related agent names when available.
  </Step>

  <Step title="Review the Current Snippet">
    The right side showed the next pending snippet for the selected rep (`/admin/feedback/pending-replies/{userId}/next`), including transcript context and the feedback thread.
  </Step>

  <Step title="Reply or Skip">
    A manager reply removed the snippet from the pending queue after refresh. Skipping also removed it by creating an internal skip reply.
  </Step>
</Steps>

## Pending Reply Logic

| Rule | Behavior |
| --- | --- |
| Tenant scope | Calls must belong to the current tenant. |
| Team-lead scope | Team leads can be limited to users in their reporting subtree. |
| User reply required | At least one reply from a regular user must exist. |
| Manager response missing | No `ADMIN`, `TEAM_LEAD`, or `INTERNAL_TOOL_ADMIN` reply can exist after the latest user reply. |
| Read status | Read status is returned, but pending status is based on reply order. |
| Sort order | Calls sort newest first; snippets inside a call sort by transcript position. |

<Note>
For the full backend selection logic, see [Snippet Selection Logic](/internal/features/backend-snippet-selection).
</Note>

## Available Actions (Removed UI)

| Action | What happens |
| --- | --- |
| Reply | Adds a manager/admin response and refreshes pending reply data. |
| Skip | Optimistically removes the snippet and creates an internal `__ZELL_MANAGER_SKIPPED__` reply. |
| Open call analysis | Opens the call recording tab and anchors to the feedback index when available. |
| Add to collection | Opens the collection dialog for the current call. |
| Load transcript context | Expands the visible transcript window above or below the snippet. |

## Empty States (Removed UI)

- If there were no pending replies, managers saw `No pending replies from your team.`
- If the selected rep had no current snippet, the viewer showed that all snippets for that rep had been reviewed.

## Operational Notes

- Load endpoint: `GET /admin/feedback/pending-replies` (still in the backend, no frontend caller)
- Next snippet endpoint: `GET /admin/feedback/pending-replies/{userId}/next` (still in the backend, no frontend caller)
- Skip endpoint: `POST /admin/feedback/pending-replies/{feedbackId}/skip` (still in the backend, no frontend caller)
- Query key: `['manager-pending-replies']`. `useFeedbackReply` (`src/hooks/api-hooks/calls/mutations/useFeedbackReply.ts`) still invalidates it after a reply, but no mounted query uses it anymore.
- Before the removal, the frontend rendered this inbox for `ADMIN` and `TEAM_LEAD` session roles.
- Verify backend route middleware before relying on team-lead access, because the admin feedback router also uses router-level admin middleware.
